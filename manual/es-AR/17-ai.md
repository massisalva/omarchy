# IA

Omarchy trae lanzadores para los agentes de programación de abajo, sin elegir uno predeterminado por vos. Ejecutá un comando para instalar su CLI la primera vez que lo uses y después iniciá sesión cuando te lo pida. Hermes es la excepción: no se instala nada para él la primera vez que lo usás, y elegirlo instala Hermes Desktop, como se explica más abajo en _Apps de escritorio_.

|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) de xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Pi, de Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), el entorno de OpenRouter |

`ori` es el bicho raro: corre los otros entornos de agentes contra todo el catálogo de modelos de OpenRouter, así que `ori claude`, `ori codex` u `ori opencode` arrancan esos agentes con el modelo que les indiques, y `ori code` es el agente propio de Ori.

### Instalar y actualizar agentes

Salvo Hermes, estos agentes usan la instalación diferida de mise: la primera vez que los abrís se instala la CLI, y las siguientes veces se reutiliza. Además, mise se fija si hay una versión nueva de un agente instalado como mucho una vez cada cuatro horas, justo antes de que arranque o en segundo plano en el prompt de la shell. Si esa actualización falla o no tenés conexión, corre la versión instalada. `omarchy update` actualiza los agentes instalados junto con el resto de Omarchy, y `mup` actualiza solo las herramientas que maneja mise.

El actualizador propio de un agente, como `claude update`, `codex update` o un botón de actualizar dentro de una app, no actualiza la instalación que maneja mise. `codex update` falla, y `claude update` puede decir que salió todo bien mientras instala una copia aparte que mise no controla. Si preferís usar el instalador y el actualizador nativos de un agente, agregalo a `disable_tools`; mirá [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas las herramientas diferidas configuradas antes de necesitarlas, ejecutá `mise install --include-lazy`. Eso incluye las otras herramientas CLI predeterminadas de Omarchy además de los agentes. Mirá [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools) para instalar una sola herramienta o usar tu propia instalación.

`grok` se instala con el paquete `grok` oficial de mise, igual que `claude` y `codex`. Ejecutá `grok`, o elegilo en _Configurar > Predeterminados > Agente_. Evitá el instalador `curl | bash` de x.ai. Ese camino pone una segunda copia en `~/.grok/bin`, la antepone en el `PATH` y pisa el wrapper de Omarchy.

### El agente predeterminado

Elegí tu agente predeterminado con `omarchy default agent <name>` o en _Configurar > Predeterminados > Agente_ en el menú de Omarchy (`Super + Space`). Si el agente todavía no está instalado, al elegirlo primero se instala. Un Omarchy recién instalado te invita a hacer esta elección con una notificación que aparece una sola vez.

Elegir Claude también intenta configurar su extensión de navegador para Chromium, Chrome, Brave, Brave Origin y Edge. La configuración de la extensión se aplica a todos los usuarios y puede pedirte la contraseña del sistema; si la cancelás o la instalación de la extensión falla, Claude queda elegido y se abre igual. Reiniciá el navegador, activá la extensión si te lo pide e iniciá sesión en Claude para terminar de conectarla. Ejecutá `/chrome` en Claude para comprobar la conexión. Firefox y Zen no soportan esta extensión. Si Claude ya era tu agente predeterminado antes de que existiera esta configuración, elegilo de nuevo para instalar la extensión.

Una vez elegido, `Super + Shift + Ctrl + A` abre el agente predeterminado en una ventana de terminal propia (o muestra el selector si todavía no elegiste). También podés mandarlo directo a una tarea con `omarchy agent prompt "Review this project"`. Los agentes que se abren así corren sin supervisión, en sus modos de no frenar a preguntar, ¡así que preparate para que hagan cosas de verdad! Y como los agentes se niegan a recordar la confianza en tu carpeta personal, si los abrís desde `$HOME` arrancan en `~/Work`.

También hay atajos para la terminal: `a` corre el agente predeterminado ahí mismo en la terminal actual, mientras que `c`, `cx` y `cy` arrancan directamente OpenCode, Claude Code y Codex (otra vez en sus modos de aprobación automática). Los cambios de tema también llegan a los agentes: Claude Code, Pi, OpenCode y Hermes (una vez que Omarchy lo instaló) siguen el tema de Omarchy cuando lo cambiás.

### El panel de agentes

La barra superior tiene un ícono de agentes. Antes de que configures un agente, su panel te guía para iniciar sesión en Claude, Codex o Grok, y el primero pasa a ser tu agente predeterminado. A partir de ahí, el panel junta todas las suscripciones en una sola página: cada agente y cuenta con su plan, un medidor para cada uno de sus límites de sesión de 5 horas y semanal con el tiempo que falta para que se renueve (pasá el cursor para ver el porcentaje exacto), o el saldo prepago que queda, debajo de una línea que va rotando lo que usaste entre todas, como los tokens de esta semana y tu modelo más usado. En _Creá algo genial_ ofrece prompts para arrancar un tema, un plugin o una app nuevos, que le pasan la tarea a tu agente predeterminado. Las apps se construyen como las propias de Omarchy, Hype, Monologue y Omacut, en C++ y Qt Quick, siguiendo la skill de agente omarchy-app, y el compilador y las piezas de Qt que necesitan vienen instalados. Claude Code, Codex, Grok, Fireworks y Kimi están cubiertos de entrada. Por ahora, Kimi informa los límites de cuota de la cuenta sin estadísticas locales de tokens ni de prompts.

Clic izquierdo en el ícono de la barra para el panel, clic derecho para abrir tu agente predeterminado. Los registros de uso detrás del panel se regeneran cada 15 minutos con `omarchy agent usage-update`, y el panel incluso puede sumar el uso de tus otras máquinas a través de una carpeta sincronizada. Mirá el README en `$OMARCHY_PATH/shell/plugins/agents/` para todos los ajustes.

### Varias suscripciones

Si pagás más de un plan de Claude, Codex o Grok — por ejemplo, un Max personal y otro del trabajo — Omarchy puede mantenerlos todos con la sesión iniciada y pasar de uno a otro. Agregá una suscripción con el + del panel de agentes, que te guía ahí mismo, o con `omarchy agent account add claude Work` (o `codex`, o `grok`). Si falta la CLI, la instala. La primera cuenta de un proveedor inicia sesión con tu navegador de siempre, justo donde la CLI busca siempre. Todas las que siguen inician sesión en una ventana privada, así no se toma por error la cuenta con la que tu navegador ya está conectado; iniciá sesión ahí con la cuenta que estás agregando, y antes cerrá cualquier ventana privada que ya tuvieras abierta. Nunca cierres la sesión de la CLI para hacer esto: cerrar sesión revoca el inicio de sesión guardado, y esa cuenta habría que agregarla de nuevo.

Para copiar los inicios de sesión de tus suscripciones a otra máquina con Omarchy por SSH, ejecutá `omarchy agent account copy user@laptop`. Si el destino no tiene un receptor instalado, el que envía pone uno temporal, así las máquinas con versiones viejas de Omarchy pueden recibir cuentas sin actualizarse. Los receptores instalados tienen prioridad. Esto copia todas las suscripciones de Claude, Codex y Grok; agregá nombres de proveedores para elegir cuáles, como en `omarchy agent account copy laptop claude`. Los nombres de cuenta y los IDs de comando quedan iguales que en el origen, incluso para cuentas que ya estaban en el destino. Las cuentas del destino que no tienen nada que ver reciben un sufijo numérico si sus nombres chocan, y los ajustes, las skills, los plugins y el historial de conversaciones quedan locales en cada máquina.

Las credenciales que ya están en el destino se conservan. Una cuenta del origen que ya tiene sesión iniciada ahí sincroniza su nombre sin reemplazar sus credenciales; las demás cuentas se agregan al lado. Para reemplazar las credenciales guardadas de las cuentas que coinciden, usá `omarchy agent account copy --replace laptop claude` después de cerrar las sesiones de esa cuenta en el destino. Un destino nuevo también recibe la cuenta activa del origen y sus preferencias de cambio de cuenta; uno que ya está en uso conserva las suyas.

Las credenciales viajan por SSH y se guardan en archivos privados en el destino, así que copiá solo a máquinas en las que confiás. Es una copia por única vez, no una sincronización continua. Otra máquina puede rotar los tokens de renovación de Codex y dejar un inicio de sesión copiado necesitando renovarse; para usar varias máquinas al mismo tiempo, lo más confiable sigue siendo iniciar sesión por separado en cada una. Mirá [la guía de autenticación de cuentas de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Hay una cuenta activa por proveedor, y cada sesión nueva arranca con ella: `cx`, `cy`, un `claude`, `codex` o `grok` a secas, cualquier cosa que se abra con `omarchy agent`, y los scripts o editores que encuentran la CLI en el `PATH`. Cambiá con `omarchy agent account use work` (y volvé con `omarchy agent account use main`), o en el panel apretando el número de una cuenta y después `Enter` (o haciendo clic en su botón Usar). Las sesiones que ya están corriendo siguen con la cuenta con la que arrancaron. El historial de conversaciones, los ajustes, las skills y los plugins se comparten entre cuentas, así que `claude --continue` en la misma carpeta sigue donde lo dejaste, ahora con la cuenta nueva.

Con más de una cuenta, el panel muestra los límites de cada una lado a lado, con la activa marcada. Por defecto, Omarchy te avisa cuando la cuenta activa pasa el 95% de un límite, y si hacés clic en la notificación cambia a la cuenta con más margen. Pasá el cursor por la línea de una cuenta en el panel y hacé clic en Cambio automático, que aparece al lado de Usar (o apretá `m`), o ejecutá `omarchy agent account mode auto`, para que cambie sola; mientras está activado, Cambio automático ocupa el lugar de Usar, y si le hacés clic otra vez vuelve a avisarte. Agregá un número para cambiar el umbral, como en `omarchy agent account mode auto 90`. Si todas las cuentas pasan el umbral, te enterás una sola vez, junto con cuál se libera primero. Mientras una cuenta activa está a 15 puntos o menos de su umbral (80% con el valor predeterminado), sus límites se revisan cada tres minutos en vez de cada 15.

`omarchy agent account list` muestra todas las cuentas con sus últimos límites, `omarchy agent account remove work` olvida una, y `omarchy agent account rename primary Hey` le cambia el nombre (o hacé clic en el nombre de una cuenta en el panel). Estos comandos trabajan con las cuentas de tu agente predeterminado; para llegar al otro proveedor, nombralo primero, como en `omarchy agent account use codex side`. El inicio de sesión que ya tenías en `~/.claude` o `~/.codex` es la cuenta _Main_ y queda donde está. Una cuenta sin usar por más de unas ocho horas puede mostrar _Se requiere iniciar sesión_; hacé clic para volver a iniciar sesión con esa cuenta ahí mismo en el panel, o arrancá una sesión con ella, que renueva el inicio de sesión sola. Los servidores MCP que tenías cuando agregaste una cuenta pasan a ella, pero los que agregues después con `claude mcp add` solo llegan a la cuenta en la que los agregaste. Claude Desktop y las herramientas configuradas con una ruta absoluta al binario de una CLI no siguen el cambio de cuenta. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícito tiene prioridad sobre la cuenta elegida.

### Diagnóstico de fallos

Omarchy vigila systemd-coredump para detectar procesos que se caen. Cuando algo hace segfault, te llega una notificación de "Process crashed" — hacé clic y el fallo pasa a tu agente predeterminado junto con la skill diagnose-crash de Omarchy, que guía al agente para sacar los datos del volcado de memoria y decidir si vale la pena reportarlo upstream. También lo podés correr a mano contra cualquier PID de `coredumpctl list` con `omarchy agent crash <pid>`.

La vigilancia viene activada por defecto. Desactivala en _Acciones > Alternar > Captura de fallos_ (o con `omarchy toggle crash-capture`) y las notificaciones paran; `omarchy agent crash <pid>` sigue funcionando a mano.

Los fallos también se pueden silenciar programa por programa, que es lo que te ofrece el diagnóstico al final. `omarchy crash mute hyprland` corta las notificaciones solo de ese programa, `omarchy crash mute hyprland off` las vuelve a activar, y `omarchy crash mute` solo lista lo que silenciaste. Acepta la ruta del binario igual que su nombre, así que `omarchy crash mute /usr/bin/hyprland` hace lo mismo. Si el nombre tiene un espacio, ponelo entre comillas, como en `omarchy crash mute 'Some App'`. Todo lo demás sigue avisando, y el programa silenciado se sigue cayendo — esto oculta el recordatorio, no arregla nada.

### Apps de escritorio

El menú _Instalar > IA_ también trae algunas apps gráficas de IA: la app de escritorio de ChatGPT, la app de escritorio de Claude (la beta para Linux de Anthropic, con las pestañas Chat, Cowork y Claude Code), Grok Bot para chatear con los modelos de xAI, Hermes Desktop, OpenClaw y la app de escritorio de Perplexity. Grok Bot es la app de chat de escritorio. El agente de programación es el comando `grok`.

Hermes Desktop es la que conviene conocer, porque una máquina tiene un solo Hermes, y es el de la app: Hermes solo se instala a través de la app, y el comando `hermes` que corre el agente predeterminado es el de la app. Elegir Hermes como agente predeterminado instala lo mismo que la opción de _Instalar > IA_: el paquete, y un entorno de Hermes en `~/.hermes` que arma el propio instalador de Hermes, lo que tarda unos minutos la primera vez. Ese entorno es el único Hermes que usan el comando `hermes` de la terminal, el agente predeterminado y la app, y se actualiza solo con `hermes update` en vez de esperar una versión de Omarchy. Al instalarlo, Hermes también recibe el tema de Omarchy como un skin llamado `omarchy`, que todas las partes de Hermes siguen cuando cambiás de tema; si no lo querés, elegí otro en los ajustes de Apariencia de Hermes o con `/skin`, y Omarchy respeta esa elección. Desinstalar la app en _Eliminar > IA_ primero cierra Hermes, gateway incluido, se lleva ese entorno y conserva tus chats, recuerdos y las skills que Hermes escribió para sí mismo, salvo que le digas lo contrario: te pregunta, con "no" como respuesta predeterminada, si esos datos y tus ajustes de conexión también se borran.

La experiencia de escritorio de OpenClaw es su Control UI, que se abre como una web app respaldada por su propio gateway local. OpenClaw vive en `~/.openclaw` y se actualiza solo: usá el botón "Update Gateway" de la Control UI o ejecutá `openclaw update`, y el gateway se reinicia con la versión nueva. Omarchy solo elige la versión con la que arranca una instalación nueva. Desinstalar OpenClaw en _Eliminar > IA_ se lleva el servicio del gateway y la app, y después te pregunta si también se borra `~/.openclaw`, ya que ahí están tus chats y credenciales junto con OpenClaw mismo y los entornos de plugins que descarga; por defecto se conserva, y si volvés a instalar OpenClaw lo retoma.

### LLMs locales

Omarchy recomienda dos formas de correr modelos LLM locales: LM Studio y Ollama. LM Studio tiene una interfaz gráfica para buscar modelos de pesos abiertos, instalarlos y correrlos. Es una gran forma de arrancar sin complicarse. Ollama ofrece una CLI para hacer algo parecido. Pero si recién empezás con modelos locales, yo arrancaría con LM Studio. Podés instalar cualquiera de los dos en _Instalar > IA_ en el menú de Omarchy.

### La skill de Omarchy

Las skills de agente ayudan a la IA a usar herramientas específicas de una forma específica, y Omarchy trae una skill predeterminada para adaptar el sistema. Por ejemplo, retocar tu configuración de Hyprland, ajustar la barra o incluso crear un tema nuevo desde cero. Está enlazada en las carpetas de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` y cada `~/.hermes/profiles/*/skills`) y la ubicación genérica `~/.agents/skills`, así que la mayoría de los entornos de agentes la toman automáticamente.

Pero tomá esta skill como experimental. Cada modelo le va a sacar un provecho distinto. Lo mejor es correrla primero en modo plan, así tenés una idea de qué querría cambiar el agente. Y después estar preparado para deshacer cambios o incluso ejecutar `omarchy reinstall configs`, si el agente te deja todo hecho un desastre.
